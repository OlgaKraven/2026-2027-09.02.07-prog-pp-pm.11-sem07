# Приложение магазина «Пара»: C# WPF и MySQL/XAMPP

Приложение использует базу учебной практики ПМ.11 и дополняет её каталогом, входом по логину, корзиной и управлением заказами в рамках производственной практики ПМ.11. Это демонстрационный пример для сверки после собственной реализации.

В phpMyAdmin создайте отдельную БД pp11_demo с utf8mb4_bin. Импортируйте materials/demo/baseline.sql. Затем выполните SQL из database в порядке 00_training_users, 01_price, 02_checkout, 03_manage, 04_read. Добавлены учебные логины pp_client, pp_manager и pp_admin. Их ФИО вымышлены; исходные строки данных не заменяются. Исторические цены из учебной БД сохраняются.

В phpMyAdmin создайте четыре учётные записи СУБД pp11_demo_login, pp11_demo_client, pp11_demo_manager, pp11_demo_admin, хост localhost, без глобальных прав. Задайте собственные локальные пароли. Выполните database/05_access.sql. Имена для своей БД должны начинаться с pp11_ и заканчиваться _login, _client, _manager, _admin. Не выдавайте SELECT/UPDATE/DROP на таблицы этим подключениям; приложение работает через разрешённые процедуры.

Откройте app/ShopDb.csproj в Visual Studio 2026. Настройте settings.local.json по settings.example.json; для своей области замените Company, Database и User ID. Пакет MySqlConnector 2.5.0 подключён в csproj; если он ещё не установлен в учебной среде, подготовьте его с преподавателем. Сборка → Собрать решение, затем Ctrl+F5. Вход по логину приложения не требует пароля; это условие учебного сценария. Пароли подключений СУБД существуют отдельно. Наличие всех подключений в локальном desktop-клиенте и вход по одному логину не являются полноценной защитой промышленной системы.

Гость смотрит каталог и карточку. Клиент ищет, фильтрует, сортирует, выбирает размер и количество, меняет корзину и подтверждает заказ. Сотрудник выбирает клиента заказа, открывает список и состав заказов, добавляет и удаляет заказ. Администратор также меняет дату и удаляет отдельную позицию. Удаление возвращает товар в остаток, последняя удалённая строка удаляет пустой заказ. После операций список обновляется. Окончательная цена определяется сервером при подтверждении; сумма корзины предварительная. Ошибка с известным откатом позволяет изменить корзину; при неясном сетевом исходе повторяйте подтверждение с тем же ключом, пока приложение открыто. После закрытия приложения сверяйте состояние заказа с БД перед повторной покупкой.

Скидка 25% действует, когда у модели нет заказов в предыдущем календарном месяце. Текущий каталог пересчитывается по дате; unit_price ранее оформленного заказа не изменяется. Конкурирующие операции используют блокировки и откат. Приложение не вызывает исходную процедуру place_order, которая сохраняет базовую цену: вместо неё используется pp_checkout.

Для резервной копии в phpMyAdmin: Экспорт → Обычный → SQL; включите структуру, данные и процедуры/функции. Восстановите в отдельную БД, вновь назначьте точечные GRANT из 05_access.sql с новым именем БД, измените Database в локальных настройках, повторите вход, каталог и заказ. Учётные записи сервера в обычный экспорт одной БД не входят. DEFINER должен существовать на сервере восстановления; пример проверяется на том же учебном сервере.
